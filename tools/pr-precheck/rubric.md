# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff matches the plan | The diff's changed files and hunks, read against the plan's scope pair (in scope / not in scope), its files list, its approach steps, and any deviation notes; then the description's claims about what changed, read against the diff | Every changed file and hunk falls inside the plan's stated scope or is recorded in a deviation note, every item the plan promises is present in the diff or its absence is disclosed in the description or a deviation note, and every concrete claim in the description (a file, a doc, a test, a behavior, "exactly as planned", "no other changes") is true of the diff. Fails if the diff silently adds work the plan scoped out or never named (a new flag, a new config option, a rename pass, a rewrite of a neighboring function), if a promised piece is missing with no note, or if the description claims more, less, or something other than the diff delivers. A deferral the plan names and the description restates is not drift. | required |
| Test evidence is decisive | The test-evidence section, read against the plan's test plan and the repro evidence's own steps; and the repo's own checks, when the plan's test plan or the repo facts name them as required | The evidence re-runs the plan's repro or test plan on the path the fix changes and shows an observable outcome before and after (an output, an exit code, a value, a crash that no longer occurs), so a reader can see the fix changed the behavior. Fails if the evidence is only a claim ("tested locally", "tests pass", "works on my machine") with nothing named or shown, if it exercises only the unchanged or control path while the plan's repro is never re-run, if an added test covers something other than the fix, or if a check the plan or repo facts require is never shown. A failing check reported honestly with its reason counts as evidence; a check hidden does not. | required |
| Diff is reviewable | The unified diff and the commit list, read hunk by hunk for what is not the fix | The diff shows the fix and nothing that buries it: no debug prints or logging left in, no commented-out code or abandoned first attempts, no dead or unused functions or imports, no TODO notes about the change itself, no formatting, re-indent, or import-reordering churn, and no unrelated hunks. Fails if any such debris or churn appears in the diff, even when the core fix inside it is correct and well evidenced. Commit message style never decides this check; only what the diff contains does. | required |
| Repo template and policy are honored | The description read against the repo facts' stated PR-template asks and contribution policy, and, where the thread has explicit maintainer direction, the description and plan read against that direction | Every section or item the repo's template or contributing guide requires is present with real content (the issue reference such as Closes #N, the checklist items, the changelog or doc entry when it is demanded, and the entry visible in the diff when the template says the diff must carry it), and, when the repo states an AI-use policy that requires disclosure, the description contains a disclosure sentence naming the tool and the extent of its use. Every package graded here is AI-assisted work, so silence never satisfies a stated disclosure requirement, however good the fix is. When a maintainer in the thread named a cause, location, or approach, the PR follows it or explains the departure. Fails on any one visible miss. A repo with no template and no stated AI policy needs neither, and passes this check on those grounds. | required |
| Honest about shortfalls | The description's notes and the plan's deviation notes, read against what the diff and evidence actually establish | Anything the PR left out, deferred, or changed from the plan is named plainly in the description or a deviation note, and the description does not present untested or unfinished work as done. This check is feedback, not a gate: a PR that is faithful, tested, clean, and compliant needs no confession to pass here. | preferred |

## Verdict rule

Accept only if all four required checks (Diff matches the plan, Test evidence is decisive, Diff is reviewable, Repo template and policy are honored) grade `pass`. If any required check grades `fail`, the verdict is `reject`. Treat `unclear` as `fail`: a PR whose fidelity, evidence, cleanliness, or compliance cannot be verified from the package is not ready to submit. The preferred Honesty check never changes the verdict either way; report it for feedback only. A PR that discloses a shortfall honestly and is otherwise faithful, evidenced, clean, and compliant is ready: grade the disclosed deferral as inside the plan, not as drift.
